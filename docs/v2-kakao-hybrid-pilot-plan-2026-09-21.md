## 1. 배경

V2는 카카오 로그인, 회원 연결/승인, 일정 생성·수정·취소, 참석/불참/미정, 댓글, 개인 프로필, AI 일정 입력 등 핵심 회원 기능이 구현된 상태다.

기술적으로는 V2 단독 운영이 가능해지고 있지만 실제 전환의 핵심 위험은 기능 부족이 아니라 **회원의 기존 사용 습관을 바꾸는 비용**이다.

현재 회원들은 카카오톡 안에서 다음 흐름에 익숙하다.

- 일정 생성
- 참석/불참 선택
- 댓글 작성
- 카톡방에서 일정 공유와 대화
- 일정 변경 또는 취소 확인

V2를 완전히 공식 도구로 전환하면 일정 관리 기능은 좋아지지만, 회원은 카카오톡에서 별도 홈페이지로 이동해야 한다. 특히 새로운 앱/웹 사용에 익숙하지 않은 회원에게는 이 한 단계가 실제 이용 장벽이 될 수 있다.

따라서 지금 단계에서는 운영 방식을 먼저 확정하지 않고, **10월을 파일럿 기간으로 사용해 실제 회원 경험을 비교한 뒤 운영진이 결정**한다.

## 2. 운영진이 최종적으로 선택할 세 가지 모델

| 모델 | 공식 원본(Source of Truth) | 카카오톡 역할 | V2 역할 |
| --- | --- | --- | --- |
| A. 홈페이지 완전 대체 | V2 | 공지·대화·V2 링크 공유 | 일정·참석·댓글 공식 관리 |
| B. 홈페이지 확인용 | 카카오 | 일정·참석·댓글 공식 관리 | 카카오 일정의 조회·정리·통계 화면 |
| C. 현 상태 유지 | 카카오 | 현재와 동일 | 보조 또는 미사용 |

중요한 원칙은 **한 일정의 공식 원본을 동시에 두 곳에 만들지 않는 것**이다.

카카오와 V2 양쪽에서 같은 일정의 참석/불참 또는 댓글을 각각 수정할 수 있게 하면 데이터가 즉시 갈라질 수 있다. 회원이 어느 쪽을 믿어야 하는지도 불명확해진다.

## 3. 10월 파일럿 권장안

### 3.1 기본 운영: Kakao 우선 + V2 Review

이미 10월 일정이 카카오톡에 등록되어 있으므로 이를 버리거나 다시 입력하지 않는다.

10월의 실제 일정은 우선 다음과 같이 운영한다.

**카카오톡 = 공식 원본**

**V2 = 읽기 전용 Review / Mirror**

회원은 기존과 똑같이 카카오에서 일정 확인, 참석/불참, 댓글, 취소를 사용한다. V2에서는 카카오 일정들을 달력, 내 일정, 모집 현황 등 더 보기 좋은 형태로 확인한다.

카톡방에서는 필요할 때 다음 정도로 V2를 자연스럽게 노출한다.

> 10월 전체 일정 한눈에 보기 → 테니스 봄

즉, 파일럿 초반에는 회원에게 새로운 행동을 강제하지 않는다.

### 3.2 별도 실험: 소수 회원 V2 전용 일정

운영진과 협조 가능한 회원 몇 명을 대상으로 `[테스트]` 일정 2~3개를 V2에만 생성한다.

이 일정에서는 실제 V2 전체 흐름을 사용한다.

1. V2 일정 확인
2. 참석 / 불참 / 미정 변경
3. 댓글 작성 및 삭제
4. 일정 수정
5. 카카오톡에 V2 일정 링크 공유
6. 일정 취소

이렇게 하면 같은 기간에 아래 두 경험을 비교할 수 있다.

- **A 경험:** 기존 카카오 방식 + V2 조회
- **B 경험:** V2 중심 운영 + 카카오 링크 공유

## 4. Kakao Mirror 구현 원칙

### 4.1 읽기 전용이어야 한다

카카오에서 동기화된 일정은 V2 화면에서 다음 작업을 허용하지 않는다.

- V2 참석/불참 변경
- V2 댓글 작성
- V2에서 일정 수정
- V2에서 일정 취소

대신 다음 안내를 명확히 표시한다.

> 카카오 일정
>
> 참석·불참 및 댓글은 카카오톡 일정에서 관리됩니다.

### 4.2 마지막 동기화 시각을 항상 보여준다

동기화가 실시간이 아니므로 카카오 Mirror를 최신 실시간 데이터처럼 보이게 하면 안 된다.

예:

> 마지막 동기화: 2026-10-05 09:00

급한 일정 변경이나 취소는 카카오가 최종 기준임을 알 수 있어야 한다.

### 4.3 데이터 출처를 UI에서 구분한다

권장 표시는 다음과 같다.

- `Kakao` / 카카오 일정
- `Tennis Bom` / V2 일정

색상이나 아이콘은 구현 단계에서 기존 UI와 조화를 보고 결정한다. 출처 표시는 디자인 목적이 아니라 **공식 원본과 편집 가능 여부를 사용자가 이해하게 하는 목적**이다.

### 4.4 두 종류 일정은 한 달력에서 함께 볼 수 있다

파일럿에서는 카카오 일정과 V2 전용 `[테스트]` 일정을 같은 Home / Schedule에서 볼 수 있는 방향을 우선 검토한다.

다만 데이터 저장은 섞지 않는다.

## 5. 현재 동기화 프로그램과 V2의 관계

현재 `카카오 일정 동기화.command`는 다음 데이터를 검증해 가져올 수 있다.

- 일정 제목·날짜·시간
- 장소/코트 정보
- 참석자
- 불참자
- 개설자
- 카카오 댓글과 댓글 수
- 취소/활성 상태 판단에 필요한 정보
- 마지막 확인 시각

또한 검증 상태, stale cache, 미해결 사용자, ghost 일정 등을 구분하고 검증된 데이터만 반영하는 안전장치를 갖고 있다.

하지만 현재 실제 Supabase 반영 경로는 V1 계열의 기존 `schedules`, `events`, `kakao_schedule_comments` 등을 대상으로 한다.

V2의 독립 운영 데이터는 다음 전용 구조를 사용한다.

- `v2_schedules`
- `v2_schedule_rsvps`
- `v2_discussions`

따라서 **현재 `.command`를 그대로 실행하는 것만으로 V2 Mirror가 갱신되는 구조는 아니다.**

## 6. 권장 기술 구조

V2 전용 일정과 카카오 Mirror 데이터를 같은 쓰기 모델로 합치지 않는다.

권장 구조는 다음과 같다.

```text
KakaoTalk
   ↓
기존 kakao-schedule 수집/검증
   ↓
Kakao Mirror 저장 영역 (읽기 전용 원본)
   ↓
V2 조회 어댑터
   ↓
Home / Schedule에 표시

V2 회원 직접 생성 일정
   ↓
v2_schedules / v2_schedule_rsvps / v2_discussions
   ↓
Home / Schedule에 표시
```

구체적인 Mirror 저장 방식은 구현 전에 다시 비교한다.

후보:

1. 기존 V1 Kakao 데이터를 V2가 읽기 전용으로 조회
2. V2 전용 Kakao Mirror 테이블을 추가
3. 동기화 결과 JSON을 별도 읽기 데이터로 제공

선택 기준은 다음과 같다.

- V1 동작을 변경하지 않을 것
- V2 회원 일정에 카카오 동기화가 덮어쓰지 않을 것
- 카카오 일정의 삭제/취소/참석 변경을 안전하게 갱신할 수 있을 것
- 나중에 카카오 Mirror를 끄더라도 V2 자체 일정 구조를 다시 바꾸지 않아도 될 것

### 6.1 Phase 1 조사 결과 및 파일럿 1차 결정 (2026-09-21)

현재 운영 DB와 V2 코드를 읽기 전용으로 확인한 결과, **파일럿 1차는 별도 Kakao Mirror 테이블을 만들지 않고 기존 `schedules`의 카카오 원본을 V2가 직접 읽는 방식**을 우선 채택한다.

확인 결과:

- 기존 `schedules`에는 `source='kakao'` 일정이 이미 계속 동기화되고 있다.
- `schedules` SELECT는 현재 공개 읽기가 가능하여 V2 카카오 로그인 회원용 조회를 위해 새 DB 권한을 추가할 필요가 없다.
- 카카오 원본 참석/불참은 `kakao_attendee_ids`, `kakao_absentee_ids`로 별도 보존된다.
- `kakao_comment_count`, `kakao_synced_at`, `kakao_deeplink`, `kakao_creator_name` 등 기존 V2 화면이 재사용할 수 있는 메타데이터도 이미 존재한다.
- 카카오 댓글 전문 `kakao_schedule_comments`는 별도 열람 권한이 적용되어 있다. 파일럿 1차에는 댓글 전문을 노출하지 않고 댓글 수만 사용한다.
- 전역 마지막 성공 동기화 시각은 `kakao_sync_state`에서 읽을 수 있다.
- 2026-09-21 확인 시 10월 카카오 일정은 20건이 존재한다. V2의 10월 일정 2건은 모두 취소된 독립 V2 일정이라 현재 활성 일정 중복은 없다.

따라서 파일럿 1차 조회 구조는 다음과 같이 한다.

```text
기존 Kakao sync
   ↓
public.schedules (source = kakao)
   ↓  READ ONLY
V2 Kakao Mirror adapter
   ↓
Home / Schedule 통합 표시

public.v2_schedules / v2_schedule_rsvps / v2_discussions
   ↓
기존 V2 직접 일정
```

파일럿 초기 범위는 **2026-10-01 이후 10월 일정**으로 제한한다. 9월에는 V1에서 일회성 복사한 일정이 V2에 존재하므로, 카카오 Mirror를 9월까지 즉시 확장하면 동일 일정이 중복 표시될 수 있다.

카카오 일정에 사용할 값:

- 일정 기본정보: 기존 `schedules` 행
- 참석: `kakao_attendee_ids`
- 불참: `kakao_absentee_ids`
- 개설자: `kakao_creator_name`
- 댓글: `kakao_comment_count`만 표시, 전문 미조회
- 일정 원문 이동: `kakao_deeplink`가 유효한 경우 사용
- 마지막 동기화: 우선 `kakao_sync_state.completed_at`을 화면 공통 기준으로 표시

파일럿 1차에서 **사용하지 않을 값**:

- V1 홈페이지에서 덮어쓴 `attendee_ids` / `absentee_ids`
- `schedule_rsvp_overrides`
- 카카오 댓글 전문

이 결정의 장점은 DB migration 없이 프런트 조회 경로만 추가하면 되고, 실패 시 해당 조회만 제거하면 현재 독립 V2로 즉시 복귀할 수 있다는 점이다. 파일럿 결과에서 장기 독립 보관이나 권한 분리가 필요하다고 판단될 때만 별도 Mirror 테이블을 다시 검토한다.

- [x] 이름 선택은 개인화 용도이며 `kakao_attendee_ids` / `kakao_absentee_ids` 기준으로 `내 일정`을 계산.
- [x] 상단에서 본인 이름을 다시 선택할 수 있도록 구현.
- [x] Review Mode에서는 `v2_schedules`, `v2_schedule_rsvps`, `v2_discussions`를 조회·수정하지 않고 Kakao Mirror + 회원/코트 정보만 사용.
- [x] Review Mode 데스크톱 1280×900 / 모바일 390×844 자동 브라우저 테스트 통과.
- [x] 개별 일정 링크 공유 기능 구현 및 운영 화면에서 실제 공유창/복사 동작 검증.
- [ ] 카톡방에 V2 전체 일정/개별 일정 링크를 실제 회원 대상으로 공유.
- [ ] 오류·불편은 V2 `의견 보내기` 또는 카카오로 수집.

### Phase 4 — 운영진 평가

파일럿 종료 후 다음 세 모델 중 하나를 선택한다.

- V2 완전 전환
- Kakao + V2 Review 하이브리드 유지
- 카카오 현행 유지

선택 후에만 장기 동기화 자동화, 화면 단순화, V1 종료 여부 등을 결정한다.

## 8. 파일럿에서 실제로 볼 지표

단순 만족도보다 **실제 행동**을 우선 본다.

### 핵심 관찰

- 카톡방에 올라온 V2 링크를 회원들이 실제로 누르는가?
- 링크로 들어온 뒤 일정 내용을 문제없이 찾는가?
- 몇 번 사용한 뒤 카톡 링크 없이 V2를 직접 다시 방문하는가?
- V2 RSVP가 카카오 RSVP보다 불편하다고 느끼는가?
- 댓글은 어디에 남기는 것을 더 자연스럽게 느끼는가?
- 운영진의 일정 등록/변경/취소 작업은 어느 방식이 적은가?
- 동기화 지연 때문에 실제 혼선이 발생하는가?

### 파일럿 종료 질문 예시

회원에게는 길게 설문하지 않고 다음 정도를 묻는다.

1. 일정 확인은 카카오와 홈페이지 중 어느 쪽이 편했는가?
2. 참석/불참까지 홈페이지에서 눌러도 괜찮은가?
3. 댓글도 홈페이지에서 작성하는 방식이 불편한가?
4. 카카오 일정 방식 그대로 유지하는 것이 좋은가?
5. 사용하면서 가장 불편했던 한 가지는 무엇인가?

## 9. UX 원칙

파일럿 기간에는 회원에게 새 도구를 배우게 하는 방향보다 **새 행동 수를 줄이는 방향**을 우선한다.

- 카카오톡을 주요 진입점으로 계속 활용한다.
- 가능한 경우 한 번의 링크 탭으로 해당 일정 상세에 바로 도착하게 한다.
- Review Mode에서는 최초 1회 공용 비밀번호 + 본인 이름 선택만 요구한다.
- 이후에는 선택한 이름 기준으로 `내 일정`을 바로 보여준다.
- 카카오 일정인지 V2 일정인지 회원이 추측하게 만들지 않는다.
- 동기화 지연을 숨기지 않는다.
- "새 홈페이지를 사용해 주세요"보다 "10월 일정 한눈에 보기"처럼 즉시 느낄 수 있는 효용을 먼저 제공한다.

## 10. 하지 않을 것

파일럿 이전 또는 중간에 다음 작업은 하지 않는다.

- 10월 카카오 일정을 모두 삭제하고 V2로 강제 이전
- 같은 일정의 참석/댓글을 카카오와 V2 양쪽에서 동시에 수정 가능하게 운영
- 카카오 데이터를 `v2_schedules`에 무조건 덮어쓰는 단순 반복 동기화
- 회원 반응 확인 전 V1/카카오 sync 중단
- 파일럿 결과 없이 별도 앱 설치나 복잡한 사용 교육을 요구

## 11. 현재 권장 다음 작업

Phase 1과 Phase 2의 핵심 구현은 완료되었고, Phase 3은 **Review Mode 실사용 파일럿**으로 전환했다.

우선순위:

1. 운영 주소에 Review Mode를 배포하고 공용 비밀번호 → 본인 이름 선택 흐름을 실제 Chrome/모바일에서 확인.
2. 기존 10월 Kakao 일정은 읽기 전용 Review로 사용.
3. 카카오톡방에 개별 일정 링크를 실제로 공유하고 회원 진입 경험을 확인.
4. 선택한 이름 기준 `내 일정`이 실제 Kakao 참석 정보와 맞는지 확인.
5. 파일럿 중 실제 불편과 혼선을 기록.
6. 별도로 Kakao 취소/삭제/ghost 일정의 V2 표시 정책을 확정.
