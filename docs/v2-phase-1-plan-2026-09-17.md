## 1. 현재 구현 상태

### 저장소와 배포

- 로컬 경로, `main` 브랜치, origin remote가 V2 저장소와 일치한다.
- 로컬·원격 main의 마지막 커밋은 위 기준 커밋과 일치했다.
- 점검 당시 추적 파일 변경은 없고, 미추적 `.textClipping` 파일 1개가 있었다. 해당 파일은 읽거나 추가하지 않았다.
- V2 사이트는 HTTP 200이며, 서비스 중인 `index.html`·`env.js`는 로컬 파일과 일치했다.
- 기준 커밋의 Pages 워크플로는 성공했다: https://github.com/cafeSowoo/tennis-homepage-v2/actions/runs/35118375336

### 인증과 회원 연결

- V2 로그인은 `provider: "kakao"`로 전환됐다. V1은 Google 로그인을 유지한다.
- Supabase 공개 Auth 설정 응답에서 Google·Kakao Provider가 모두 활성화된 것을 확인했다.
- V2 전용 Auth storage key `tennis-homepage-v2-auth`가 적용됐다.
- 로그아웃은 `signOut({ scope: "local" })`을 사용한다.
- Supabase JS는 `2.116.0`으로 고정돼 있다.
- 실행 코드의 고정값 `MY_NAME = "김지석"`는 제거됐으며 `myMemberId()`, `myMember()`, `myMemberName()` 등으로 대체됐다.
- 연결 구조는 `auth.users.id → club_member_accounts.user_id → member_id → members.id`이다.
- 최초 로그인 시 본인 계정 행이 없으면 pending 행을 생성한다. approved 계정은 기존 회원과 연결되고 pending/disabled 상태를 표시한다.
- 회원 승인 UI는 아직 없다. 초기 승인 테스트는 관리 도구에서 기존 회원과 연결하는 설계다.

### DB 설계 검토

기준 파일: `supabase/migrations/20260916152242_club_member_accounts_and_member_rsvp.sql`

- 일반 회원은 본인 pending 계정을 생성하고 자기 계정을 조회할 수 있다. 스스로 승인하거나 회원 연결·관리자 권한을 부여할 수 없다.
- `member_id`는 UNIQUE가 아니므로 같은 회원에 Google·Kakao 계정을 각각 연결할 수 있다.
- 관리자 계정 seed/link와 계정 관리용 RLS가 존재한다.
- public `set_my_schedule_rsvp()`는 SECURITY INVOKER wrapper이며 실제 쓰기는 `club_private`의 제한된 SECURITY DEFINER 함수가 수행한다.
- 본인 RSVP 함수는 `member_id`를 입력받지 않는다. 로그인 사용자와 승인된 활성 회원 연결을 서버에서 확인한다.
- 일정 행 잠금, 허용 상태, 마감, 16명 정원을 검사한다.
- Kakao 일정은 기존 RSVP override와 trigger를 이용하고, 일반 일정은 본인의 참석·불참 상태를 갱신한다.
- 기존 Google 관리자 쓰기 정책을 삭제하거나 대체하지 않는다.

원격 DB에 마이그레이션이 적용됐다는 점과 Supabase의 `Allow users without an email` 활성화는 사용자 제공 사실을 전제로 했다. 이번 점검에서 원격 정책 전문이나 관리자 설정 화면을 재조회하지 않았다. OAuth 응답 확인은 Kakao로 보내는 302 응답까지만 수행했으며, 로그인 완료·동의·회원 생성은 수행하지 않았다.

## 2. 발견된 문제

### 2.1 회원 쓰기 기능 미완성

- 프론트엔드 RSVP가 새 `set_my_schedule_rsvp()`에 연결되지 않고 기존 관리자용 참석자 배열 수정·불참 저장 경로를 사용한다.
- 댓글 작성은 승인 회원 확인 후에도 `requireOfficialWriteAccess()`를 호출하므로 일반 Kakao 회원은 승인돼도 저장할 수 없다.
- 저장소 SQL에 회원 댓글 작성·삭제 정책이 없고, 댓글 삭제 UI도 없다.
- `isClubAdmin()`은 존재하지만 공식 데이터 수정 권한은 여전히 owner 이메일 기준이다. 이메일 없는 Kakao 계정의 `role=admin`만으로 기존 관리자 기능을 사용할 수 없다.
- 참석자 추가·제거 등 관리자 UI가 일반 사용자에게도 노출된다. 실제 DB 권한과 표시를 구분해 정리해야 한다.
- `카카오 상태 따르기`는 기존 관리자 RPC의 override 삭제 기능이다. 새 회원 RPC는 `null` 상태를 허용하지 않아 회원용 복귀 경로가 없다. `pending`은 override 삭제와 같지 않다.
- Kakao 댓글 전문 열람은 기존 `kakao_comment_readers` 정책을 사용한다. 새 회원 승인만으로 자동 열람 가능해지는 구조는 아니다.

### 2.2 V1과 브라우저 저장소 충돌 가능성

- Auth key는 분리됐지만 일정·이벤트·알림·PWA 설치 안내 등 `tennis.*` localStorage 키는 V1과 동일하다.
- 공식 원격 쓰기 모드에서는 일부 로컬 override가 사용되지 않지만, 알림·설치 안내와 로컬 모드 또는 fallback 경로의 공유 가능성은 남는다.
- `sw.js`의 activate 처리가 현재 캐시 외의 같은 origin 캐시를 모두 삭제하므로 V1 캐시에 영향을 줄 수 있다.
- 서비스워커 알림 클릭 처리가 경로 대신 origin으로 창을 선택해 V1 창을 V2로 이동시킬 가능성이 있다.
- V1에도 광범위한 캐시 삭제 코드가 남아 있다. V2 측 변경으로 V1에 주는 영향을 줄일 수 있지만, V1을 수정하지 않는 범위에서 상호 캐시 간섭이 완전히 없어졌다고 단정하지 않는다.

### 2.3 배포와 URL 불일치 위험

- 로컬·현재 서비스 중인 `env.js`의 `siteUrl`, `authRedirectUrl()`의 GitHub Pages 반환 주소는 V2 URL과 일치한다.
- `.github/workflows/pages.yml`의 `SITE_URL` 기본값은 V1 URL이다.
- 점검 시 저장소 및 `github-pages` 환경에서 `SITE_URL` 변수를 찾지 못했다.
- GitHub Pages 설정은 `build_type: legacy`, `main` 루트 배포로 나타나며 Actions 배포 워크플로도 존재한다.
- 현재 서비스 중인 `sw.js`에는 `__CACHE_VERSION__`이 치환되지 않고 남아 있었다.
- 따라서 다음 배포 전 실제 배포 경로를 정리하고, 산출물의 URL과 캐시 버전을 확인해야 한다.
- `club/index.html`의 공유 메타데이터에도 V1 URL이 남아 있다. OAuth 원인은 아니며 후속 정리 대상으로 구분한다.

### 2.4 기존 설계 문서의 상태 설명

기존 구현계획의 “Kakao 미적용”, “MY_NAME 유지”, “siteUrl이 V1”은 현재 코드와 다르다. 단계별 작업 완료 후 문서 상태를 갱신한다.

## 3. Kakao KOE205 원인과 최소 수정안

가장 가능성 높은 원인은 Supabase Kakao Provider가 기본으로 추가하는 `account_email`과 이메일 동의를 사용하지 않는 Kakao 앱 설정의 불일치다.

현재 프론트엔드는 scope를 직접 지정하지 않는다. Supabase 공식 Provider 소스는 기본 scope에 이메일·사진·닉네임을 포함하고, `options.scopes` 값은 기본 목록에 추가한다.

현재 프로젝트에 대해 확인한 OAuth 302 응답:

| 요청 | 실제 Kakao scope |
|---|---|
| 현재와 같은 기본 요청 | `account_email profile_image profile_nickname` |
| `options.scopes`에 닉네임·사진 지정 | 이메일 유지, 닉네임·사진 중복 추가 |
| `queryParams.scope`에 닉네임·사진 지정 | `profile_nickname profile_image`만 전달 |

`Allow users without an email`은 이메일 없는 사용자 응답을 허용하는 설정이다. 현재 확인한 동작에서는 이 설정만으로 기본 요청 scope가 제거되지 않는다.

첫 구현 범위는 `index.html`의 `handleAuthButton()`에서 OAuth 옵션만 다음처럼 최소 수정하는 것이다. 2026-09-17 사용자 진행 요청에 따라 아래 변경을 적용했다.

```js
options: {
  redirectTo: authRedirectUrl(),
  queryParams: {
    scope: "profile_nickname profile_image"
  }
}
```

이 방식으로 이메일 scope가 빠지는 것까지 확인했다. 최종 Kakao 로그인, Supabase 세션 발급, pending 생성은 후속 검증 대상이다. 이 문제 해결을 위해 기존 테이블·정책 변경이나 인증 구조 재작성이 필요하다는 근거는 없다.

### Redirect의 두 단계

1. Kakao → Supabase: `https://myincubzgvhyreyqbban.supabase.co/auth/v1/callback`
   - 실제 OAuth 요청에서 확인했다.
   - Kakao 앱의 Redirect URI에는 이 callback이 등록돼 있어야 한다.
2. Supabase → V2: `https://cafesowoo.github.io/tennis-homepage-v2/`
   - 코드와 현재 배포 파일은 일치한다.
   - Supabase Redirect allow list 등록 여부는 관리자 설정에서 추가 확인해야 한다.

공유 Supabase의 Site URL을 V2로 일괄 변경하지 않는다. 기존 V1 설정을 유지하면서 V2 반환 주소의 allow list 등록을 확인하는 방향으로 진행한다.

## 실행 기록 — 2026-09-17, 1단계 최소 수정

- 사용자 진행 요청에 따라 `index.html`의 로그인 옵션에 `queryParams.scope`를 추가했다. 기존 provider, 반환 주소, 세션 키 및 로그아웃 처리는 유지했다.
- 수정된 `handleAuthButton()`을 격리된 Node VM에서 실행해 OAuth 호출 인자를 추출하고, 페이지와 동일한 CDN의 Supabase JS `2.116.0`으로 authorize URL을 생성했다.
- SDK 검증은 세션 저장·자동 갱신·URL 세션 감지를 끈 임시 클라이언트로 진행했다. 브라우저 기존 세션과 서비스워커는 사용하지 않았다.

- 수정 후 inline JavaScript 문법 파싱이 통과했다.
- 실제 Kakao 로그인·동의 및 회원 생성은 진행하지 않았다. 별도 브라우저 프로필 검증과 로그인 후 세션·pending 확인은 남아 있다.
- DB 스키마/정책, 원격 설정, V1, `.textClipping`은 변경하지 않았다. 커밋·배포는 진행하지 않았다.

## 실행 기록 — 2026-09-17, 가능한 후속 구현

사용자가 1차 계획에서 진행 가능한 부분을 이어서 처리하도록 요청했다. 로그인·원격 DB 변경 없이 수행 가능한 로컬 구현을 진행했다. 위 초기 점검 내용은 당시 상태의 기록이며 아래 변경 사항을 함께 참고한다.

### 완료한 변경

- V2 localStorage 키를 `tennis.v2.*`로 분리했다. 기존 V1 데이터는 복사·삭제·수정하지 않았다. V2의 기존 로컬 알림·설치 안내 설정은 새 키에서 시작한다.
- V2 서비스워커는 `tennis-homepage-v2-` 캐시만 정리하고 현재 캐시에서만 조회한다. fetch·알림 URL과 대상 창은 앱 scope 안으로 제한했다.
- OAuth 정보를 읽기 전에 history가 URL hash를 제거할 가능성을 피하도록 Auth 초기화 순서를 수정했다.
- 계정이 바뀌거나 로그아웃된 뒤 늦게 도착한 회원 조회 결과가 현재 상태를 덮어쓰지 않도록 요청 식별과 사용자 일치 검사를 추가했다.
- 본인 RSVP의 참석/불참/미정은 모두 `set_my_schedule_rsvp()`로 연결했다. 임의 member ID는 전송하지 않는다. 승인·활성 회원, 잘못된 상태, 일정 존재, 마감·정원을 클라이언트에서도 확인하고 서버 검증을 유지한다.
- 같은 일정의 중복 요청을 막고 RPC 실패 시 잠금을 해제한다. 저장 후 목록 갱신이 실패하면 저장 완료와 화면 갱신 실패를 구분해 안내한다.
- 현재 DB owner 정책에 맞춰 관리 버튼은 owner에게만 표시한다. 일반 Kakao 회원의 `role=admin`만으로 기존 owner 기능을 개방하지 않았다.
- 일반 회원 댓글 작성 정책이 아직 없으므로 입력창 대신 준비 중 안내를 표시한다. 기존 owner 댓글 작성 경로는 유지했다. 회원 댓글·삭제 DB 정책은 추가하지 않았다.
- V2 저장소 secrets 목록이 비어 있음을 확인했다. workflow는 빈 secrets로 `env.js`를 생성하는 대신 이미 추적 중인 공개 클라이언트 설정을 복사하도록 수정했다. 현재 설정의 키가 publishable key임을 값 출력 없이 확인했다.
- workflow 자동 배포 trigger는 `main`만 남기고, 회원·캐시 테스트 단계를 추가했다. `club/index.html` 공유 메타데이터의 V1 주소도 V2로 변경했다.
