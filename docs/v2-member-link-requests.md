# 회원 연결 요청

- 인증 설정은 그대로 유지한다. 로그인 시 생성되는 pending 계정이 요청 RPC를 호출한다.
- 기존 회원은 requested_member_id, 신규 회원은 이름을 저장한다. 요청은 member_id/status/role을 바꾸지 않는다.
- 회원 선택 조회는 pending 미연결 계정에만 ID와 이름을 반환한다. 사진은 현재 members DB 필드에 없다.
- 관리자는 요청 내용을 참고하되 기존 승인 화면에서 회원을 직접 선택한다. 신규 회원 생성 자동화는 이번 단계에 포함되지 않으며, 기존 회원 등록 절차 후 연결한다.
- 요청 변경 시 updated_at이 갱신되어 관리자의 오래된 승인 요청은 기존 RPC에서 거부된다.

## 적용 순서

1. 운영 DB의 기존 스키마/마이그레이션 상태 확인 후 `20260918140202_v2_member_link_requests.sql` 적용 및 권한 검증.
2. 프런트 배포. 새 열을 조회하므로 DB 적용 전에 프런트만 배포하지 않는다.
3. 실제 카카오 pending 계정으로 요청, 관리자 승인, 승인 상태 확인까지 검증.

2026-09-18 운영 DB에 적용했다 (migration: 20260918140202). 프런트는 아직 배포하지 않았다.

운영 DB에서 `supabase/tests/v2_member_link_requests.sql`을 실행해 기존/신규 요청, 본인 행 접근, 직접 승인 차단, 오래된 승인 거부, 관리자 승인, 승인된 계정 및 비로그인 요청 차단을 검증했다. 테스트 계정과 회원은 트랜잭션 롤백으로 모두 제거됐으며 기존 approved/admin 2개는 유지됐다.

보안 advisor의 신규 지적은 없었다. 적용 전부터 있던 유출 비밀번호 보호 비활성화 경고 1개는 인증 설정 변경 범위가 아니므로 유지했다. 실제 카카오 pending 계정으로 로그인하는 E2E 검증은 미수행이다.
